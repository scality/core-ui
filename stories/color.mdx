# Colors

## Using a colour

Pass the **token name**, not a colour:

```jsx
<Box color="statusCritical" />
```

```js
const Alert = styled.div`
  color: ${(props) => props.theme.statusCritical};
`;
```

Both resolve against whichever theme is mounted, so they follow a theme switch and a
rebrand. A raw colour does not, which is why `Box`'s colour props no longer accept one
— a value outside the palette below fails to compile, and a near miss is corrected for
you (`statusHealty` gives _Did you mean `statusHealthy`?_).

Three keywords are still accepted, because they defer to the context rather than
naming a colour: `currentColor`, `inherit` and `transparent`. For a gradient or an
image, use `backgroundImage`.

Reading the resolved value out of the theme and passing it straight back in is the one
form to avoid:

```jsx
<Box color={theme.statusCritical} /> // no
```

It looks equivalent, but it snapshots the colour at render and bypasses the scale, so
a branded theme is not honoured.

### Overriding

The props are the paved path, not a wall. `styled()` wraps a component to override its
CSS, and the declarations inside it are plain CSS — anything the browser accepts:

```js
const Emphasis = styled(Box)`
  color: red;
  background: linear-gradient(90deg, #fff, #000);
`;
```

That still works, and it wins over a token passed as a prop on the same element, since
the wrapper's class is generated after the component's own. Reach for it where a value
genuinely belongs outside the palette — a one-off illustration, a third-party brand
colour — and reach for a token everywhere else, which is nearly always.
